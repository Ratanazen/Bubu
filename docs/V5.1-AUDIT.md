# BUBU V5.1 - REPOSITORY AUDIT

## WHAT EXISTS
- Electron/Vite/React Monorepo Structure (`apps/`, `packages/`)
- Platform Engine with basic adapters (Hyprland, Sway, Niri, KDE, etc.)
- Basic IPC structure
- Control Center React Application
- Desktop Pet Renderer
- CLI (`bubu`)
- Settings & Profiles (Context Engine base)
- Icon System using `lucide-react`
- Waybar Engine JSON generator

## WHAT WORKS
- AppImage builds and packages cleanly
- TypeScript compilation is successful (0 errors)
- Basic UI routing and icons
- CLI basic commands (`doctor`, `status`)

## WHAT IS BROKEN / PARTIAL / MOCKED
- `ScreenMapPage.tsx` falls back to hardcoded mock coordinates if `getAllDisplays` IPC fails
- Bubu location logic (x, y, scale, rotation, monitor assignment) is partially mocked or disconnected from the deep native window manager
- Window Engine / Workspace Engine tracking is partial (Hyprland queries exist but are not fully bridged to a real-time reactive central state)
- Niri, Sway, KDE, GNOME, XFCE native bindings lack full robust implementations
- Permissions Engine is not fully implemented
- Safe Mode is not implemented
- Waybar Engine lacks robust backup of `~/.config/waybar/config`
- Layers and Widget engines are conceptual
- Activity Log is missing

## ACTION PLAN (V5.1)
1. **Refactor Platform Engine**: Establish the strict `CapabilityStatus` model and verify actual IPC calls for Hyprland/Sway/X11.
2. **Build Monitor/Workspace/Window Engines**: Map the system architecture directly to the OS to feed the `ScreenMapPage`.
3. **Upgrade Bubu Location Engine**: Tie coordinates to actual OS displays and compositor window pinning.
4. **Implement Real Screen Map**: Allow zooming, panning, and actual Bubu drag-and-drop to true OS coordinates.
5. **Finalize Avatar/GIF System**: Implement style-to-primary-avatar logic without flattening GIFs.
